## Package boundaries

| Path                        | Ownership rule                                                                                                                                                                            |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/index.ts`              | App entrypoint — creates Hono app, mounts middleware + routes. Only file that imports from `middleware/` and `routes/`. Never import wrangler runtime types directly (use `AppInstance`). |
| `src/types.ts`              | `Bindings` (env vars), `Variables` (request-scoped), `AppInstance` (composite Hono type). Imported by routes and middleware, never imports from other `src/` files.                       |
| `src/routes/`               | Sub-routers only. Each file creates and exports a `Hono<AppInstance>` router. No middleware registration. No side effects at module level.                                                |
| `src/middleware/`           | Global middleware only. Each file exports handler functions. No route-specific logic.                                                                                                     |
| `src/shared/`               | Pure functions. No Hono imports. No side effects.                                                                                                                                         |
| `worker-configuration.d.ts` | Auto-generated by `cf-typegen`. Do not edit manually.                                                                                                                                     |

## Middleware execution order

Registration order in `src/index.ts` is significant:

```
app.use('*', customLogger)    // 1. Logging first (level via LOGGER_LEVELS)
app.use('*', secureHeaders()) // 2. Security headers
app.use('*', customCors)      // 3. CORS
app.onError(errorHandler)     // 4. Error catch-all (after middleware, before routes)
app.notFound(notFoundHandler) // 5. 404 fallback
app.route('/health', ...)     // 6. Routes mounted last
```

- `onError` and `notFound` must be registered **after** middleware but **before** routes
- Any middleware registered after `onError` will not be wrapped by the error handler
- Logger before headers is intentional: request logged before any response processing

## Routes — request/response conventions

See `docs/code_guidelines.md` sections Response Shape, Status Codes, and Error Handling for the full conventions.

Key points:

- Responses use `c.json()` with shape `{ success: boolean, error?: { message: string, stack?: string }, data?: unknown }`
- Stack traces only included when `ENVIRONMENT=development` (checked at runtime in `src/middleware/error.ts`)
- 404 returns `{ success: false, error: { message: "Route not found: {method} {path}" } }`
- Error handler preserves existing response status; falls back to 500 if status is 200 (unset)
- CORS middleware always allows localhost; validates against comma-separated `ALLOWED_ORIGIN` with `*` wildcard; falls back to first entry
- CORS preflight cached 86400s (24h)

## Commit convention

Format: `🎉 (scope)type: message`

| Type       | Emoji | Usage                    |
| ---------- | ----- | ------------------------ |
| `feat`     | 🎉    | New feature              |
| `fix`      | 🐛    | Bug fix                  |
| `chore`    | 🧹    | Maintenance, tooling     |
| `refactor` | ♻️    | Code restructuring       |
| `test`     | 🧪    | Adding or updating tests |
| `docs`     | 📝    | Documentation only       |
| `style`    | 💄    | Formatting, lint fixes   |
| `perf`     | ⚡️    | Performance improvement  |

Examples:

- `🎉 (app)feat: add health endpoint`
- `🐛 (middleware)fix: handle missing ALLOWED_ORIGIN env var`
- `♻️ (routes)refactor: extract user validation logic`
- `📝 (docs)docs: add architecture blueprint`

Scopes describe the changed area: `(app)`, `(middleware)`, `(routes)`, `(shared)`, `(auth)`, `(docs)`, `(infra)`, `(root)`, etc.

## Git flow

- `main` — production-ready. Only merges from `release/*` or `hotfix/*`.
- `develop` — integration branch. Feature and fix branches branch off and merge back here.
- `feature/*` — branch from `develop`, merge back to `develop`.
- `fix/*` — branch from `develop`, merge back to `develop`.
- `release/*` — branch from `develop`, merge to `main` + back to `develop`.
- `hotfix/*` — branch from `main`, merge to `main` + `develop`.

## Post-merge cleanup

After a PR is merged:

1. `git checkout develop && git pull` — sync merged changes
2. `git branch -d <branch-name>` — delete the local feature branch

For `release/*` and `hotfix/*`, repeat with `main` after merging there.

The first thing in a real project: `git checkout -b develop && git push -u origin develop`.

## Env var management

See `docs/architecture.md` §8 Operational Considerations — Env Var Management for the full details.

Non-secret vars live in `wrangler.jsonc` under `vars`. Secrets live in `.dev.vars` (local) and `wrangler secret put` (production).

Key additional rule: all env vars must be declared in `src/types.ts` under the `Bindings` type before use (the zod schema in `src/env.ts` is the single source of truth).

## Portability note

Currently wired for Cloudflare Workers (wrangler, `CloudflareBindings`, environment-specific `wrangler.jsonc`). The Hono framework is runtime-agnostic — adapting to AWS Lambda, Google Cloud Functions, etc. requires swapping only the entrypoint adapter. See `src/index.ts` as the sole platform-adapter file.

See `README.md` for portability summary and `docs/architecture.md#9-runtime-portability` for full deployment patterns and the env var compatibility shim.
